# Obsidian Properties Documentation

## Why this source matters

Explain.fm uses Obsidian properties to keep ingest metadata human-readable and machine-checkable. This page is the primary reference for supported property behavior and format.

## Scope

Property purpose, supported types, templates, YAML storage, and documented limitations. It does not define Explain.fm's ingest schema.

## Key claims and evidence

| Claim | Evidence or location | Confidence |
| --- | --- | --- |
| Properties store structured information about a note. | Introduction | High |
| Supported property types include text, lists, numbers, checkboxes, dates, date-times, and tags. | “Property types” | High |
| Templates can add and merge properties into a note. | “Advanced uses — Templates” | High |
| Properties are stored as YAML at the top of a Markdown file. | “Property format” | High |
| Nested properties, bulk editing, and Markdown in properties have documented limitations. | “Not supported” | High as of access date |

## Limitations and uncertainty

- This is first-party product documentation and can change with Obsidian releases.
- The page does not specify a documentation-content license.
- Explain.fm's validator supports only the flat subset used by its source template, not general YAML.
