# Documentation Standard

- State purpose and audience before detail.
- Distinguish current behavior, approved plans, and speculative ideas.
- Link claims about project behavior to code, tests, decisions, or evaluation evidence once those artifacts exist.
- Keep contracts technology-neutral unless an accepted ADR requires otherwise.
- Update the owning document in the same change that makes it inaccurate.
- Prefer concise Markdown, explicit headings, UTF-8 text, and relative repository links.
